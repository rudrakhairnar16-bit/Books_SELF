TOPIC 1: CLASSIFICATION AND TERMINOLOGY OF DATA STRUCTURES
A computer's physical memory is organized as a linear sequence of addressable bytes. A Data Structure is a logical,
systematic arrangement designed to represent, store, and organize data elements inside this memory, making them
accessible to the processor for fast calculations.

Real-World Applications & Examples:
• Google Maps (Non-Linear/Graph): Road intersections are stored as Vertices (nodes), and the physical roads
connecting them are stored as weighted, directed Edges representing distances or real-time traffic speeds.
• Hospital Reception (Linear/Queue): Patients are managed sequentially on a First-In, First-Out (FIFO) basis. The
patient arriving first is diagnosed and processed first.
PROFESSOR'S WARNING: Many students mistakenly classify Linked Lists as non-linear because nodes are scattered
physically across the memory heap. However, a Linked List is logically linear because elements are connected
sequentially using pointers. Always write Linear Non-Primitive for Linked Lists!
TOPIC 2: ALGORITHM PERFORMANCE & ASYMPTOTIC NOTATIONS
Algorithm analysis evaluates the efficiency of programs as the input size n approaches infinity. To ensure
independent analysis across various physical systems, hardware specs, and compilers, we measure the number of
essential computational execution steps (Time Complexity) rather than wall-clock execution time.
The Three Asymptotic Bounds:
1. Worst Case (Big-O Notation / O): The maximum number of operations an algorithm can take. Represents the
absolute upper bound.
2. Best Case (Omega Notation / Ω): The minimum number of operations required for execution. Represents the
absolute lower bound.
3. Average Case (Theta Notation / Θ): The mathematical expected number of operations averaged over random
input states.

Mathematical Loop Complexity Analysis:
A. Single Loop: runs exactly n times:
for (i = 1; i <= n; i++) print(i);
Time Complexity is O(n).
B. Nested Quadratic Loop: runs n * n times:
for (i = 1; i <= n; i++) {
    for (j = 1; j <= n; j++) print(i, j);
}
Time Complexity is O(n2).
Linear Search Complexity Breakdown:
• Best Case: Target element is located at the very first index (index 1). Requires exactly 1 comparison. Asymptotic
complexity: Ω(1).
• Worst Case: Target is at the final index (index n) or completely absent from the array, requiring a sequential scan of
all elements. Asymptotic complexity: O(n).
• Space Complexity: Requires no dynamic allocation proportional to the input size; uses only a constant pointer
tracker i. Asymptotic complexity: O(1).

TOPIC 3: 2D ARRAY MEMORY ADDRESS CALCULATION
Physical computer memory is a 1-dimensional array of addresses. To store a 2D array (grid of rows and columns) in
memory, we must flatten it using either Row-Major Order (RMO) or Column-Major Order (CMO).
Address Calculation Formulas (0-Based Indexing):
Let BA be the Base Address, W be the byte size of each data element, Rows be the total number of rows, and Cols
be the total number of columns in array A.
• Row-Major Order (RMO): Elements are stored sequentially row-by-row.
    Address(A[i][j]) = BA + (i * Cols + j) * W
• Column-Major Order (CMO): Elements are stored sequentially column-by-column.
    Address(A[i][j]) = BA + (j * Rows + i) * W
Step-by-Step Address Trace:
Given an array X[4][5], with Base Address BA = 2000 and integer size W = 4 bytes. We calculate the physical
memory address of element X[2][3]:

we multiply the column index j by Rows, not Cols. Double check this multiplication on the exam!
TOPIC 4: STACKS (LIFO OPERATIONS & BOUNDARY CONDITIONS)
A Stack is a linear, non-primitive data structure governed by the Last-In, First-Out (LIFO) principle. All insertions
(PUSH) and deletions (POP) occur at a single designated end called the TOP.

   TOP = TOP - 1
3. [Return Former Top Item]
   Return S[TOP + 1]

TOPIC 6: QUEUES & CIRCULAR QUEUES
A standard Queue is a linear list governed by the First-In, First-Out (FIFO) principle. Insertions occur at the REAR
end, while deletions occur at the FRONT end.
The Memory Wastage Limitation of Simple Queues:
In a simple queue represented by an array of size MAX, when elements are deleted, the FRONT pointer moves
forward. Once the REAR pointer reaches the final index (MAX - 1), no new elements can be inserted, even if the
beginning of the array is empty (e.g., indices 0, 1, 2 are empty due to deletions). The queue falsely reports
OVERFLOW.

The Circular Queue Solution:
A Circular Queue avoids this memory wastage by connecting the last position back to the first. If the rear pointer
reaches MAX - 1 and space is available at index 0, the rear pointer loops back to 0. The formulas use modular
arithmetic to wrap pointers.
Boundary Checks in Circular Queues:
• Circular Queue Overflow (Full):
    (FRONT == 0 && REAR == MAX-1) || (FRONT == REAR + 1)
• Circular Queue Underflow (Empty):
    FRONT == -1
Double-Ended Queue (Deque):
A Deque is a specialized linear queue where insertion and deletion operations can be performed at both ends (front
and rear). It has two variations:
1. Input-Restricted Deque: Insertion occurs only at one end (rear), while deletion is allowed at both ends.
2. Output-Restricted Deque: Deletion occurs only at one end (front), while insertion is allowed at both ends.

TOPIC 7: RECURSION
Recursion is a programming design strategy where a function calls itself either directly or indirectly to solve a
problem. It represents a large problem as smaller, identical sub-problems.
Syllabus Standard Core Functions:
Every recursive function requires a Base Case to stop recursive calls and prevent infinite execution stack overhead.
Factorial Recursive Function
Fibonacci Recursive Function
int Factorial(int n) {
    if (n == 0) 
        return 1; // Base Case
    else
        return n * Factorial(n-1);
}
int Fibonacci(int n) {
    if (n == 0) return 0; // Base Case
    if (n == 1) return 1; // Base Case
    return Fibonacci(n-1) + Fibonacci(n-2);
}

B. Quick Sort (First Element Pivot) Trace:
Initial Array: [94, 20, 13, 54, 11, 32, 3]. Set Pivot = 94. i starts at index 1 (20), j starts at index 6 (3).
• Left index scanner i moves right looking for an element > 94 (goes out of bounds at index 7).
• Right index scanner j moves left looking for an element ≤ 94 (stops at index 6, value 3).
• Pointers crossed (i > j). Swap Pivot (94) with A[j] (3).
• State after Partition 1: [3, 20, 13, 54, 11, 32, 94]. Pivot 94 is now in its permanent sorted position.
• Left subarray partition [3, 20, 13, 54, 11, 32] is recursively sorted to complete the sequence: [3, 11, 13, 20, 32, 54,
94].
