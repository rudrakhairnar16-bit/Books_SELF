Authentication
•A SQLite database is convenient for storing mobile data on smartphone 
but is not well protected.
•SQLite is not a multi-user database, which means that anyone who has 
direct access to the file can read the database content.
•SQLite must be permitted by the file access control mechanism first. 
Authentication  can  be  added  to  the  DBMS:  the  user  or  application 
provides  its identity; and  the  database  authenticates the validity of 
the user or application.  Only legitimate users or application can access 
the data in the database, e.g. created, queried, modified, inserted, 
deleted, 
modified.

===== PAGE 10 =====
DAC and MAC Access Control
•Discretionary Access Control (DAC) enforces security by means of user 
identifiers(uid) and group identifiers (gid); only the owner of the data (i.e., 
the Content Provider) holds the r/w permissions on the file.
•Mandatory Access Control (MAC)  is based on clearance, i.e., security labels 
(secret,  top  secret,  confidential,  etc.).  Data  objects  are  given  a 
security 
classification, and the user will be denied access if his clearance is 
lower than the classification of the object.
•SQLite is single user database  (whoever has direct access to the file can read 
the data), the use of DAC alone is not adequate and enough.

Data Encryption
There are two data encryption schema for SQLite
1.
Strong Encryption of  DB on the DBMS level, i.e. perform  encryption 
or decryption while DB reading/ writing where the encryption function is 
embedded into the DBMS, and the encryption and decryption process 
is transparent to users.
2.
Encrypt DB on application layer, where encryption or decryption can be 
operated on some fields of the records(fields)
3.
SQLChiper is an extension of SQLite which provide data encryption 
based on user password.

RBAC (Role-Based Access Control) Models in 
DBMS
•RBAC  (Role-Based  Access  Control)  is  a  widely  used  method  of 
restricting  system  access  to  authorized  users  based  on  their 
roles 
within an organization.
•In a Database  Management System (DBMS),  RBAC is a  security 
model  that  helps  manage  and  enforce  access  control  policies.  In 
RBAC, users are assigned roles, and roles are associated with 
specific 
permissions.
•This allows administrators to control what data users can access and 
what actions they can perform on the data, depending on the role 
assigned to them.

Advantages of RBAC in DBMS
•Simplified  Access  Control:  RBAC  reduces  complexity  by  assigning 
permissions based on roles rather than individual users, making it easier to 
manage large numbers of users.
•Security:  By  enforcing  least  privilege,  where  users  are  granted  only  the 
minimum permissions necessary for their roles, RBAC minimizes the risk of 
unauthorized access.
•Scalability: It’s easier to manage security as organizations grow. Roles can be 
quickly modified, and new users can be assigned appropriate roles without 

===== PAGE 15 =====
Disadvantages of RBAC in DBMS
•Role Explosion: In very large organizations with diverse responsibilities, 
the number of roles may become very large, leading to complexity in role 
management.
•Lack  of  Fine-Grained  Control:  RBAC  is  less  flexible  when  very 
specific permissions need to be assigned at a detailed level (e.g., certain 
users needing access to very specific data objects rather than whole sets).
•Potential for
Mismanagement:
Misassigning
users to roles with
excessive permissions can lead to security vulnerabilities.

SQL injection
•SQL Injection is one of the most common and dangerous types of database security 
vulnerabilities. It occurs when an attacker is able to manipulate a SQL query by 
injecting malicious SQL code into the input fields of an application.
•This  allows  the  attacker  to  gain  unauthorized  access  to  the  database,  retrieve 
sensitive data, modify records, or execute harmful operations such as deleting tables 
or altering data.
•SQL  Injection  exploits  the  way  SQL  queries  are  structured  and  executed  in  a 
Database Management System (DBMS), particularly when user inputs are directly 
included in SQL queries without proper validation or sanitization.

===== PAGE 18 =====
How SQL Injection Works
•SQL Injection typically works by exploiting improper handling of user inputs 
in web applications or software that interact with databases. For example, if a 
website or application allows a user to log in by submitting a username and 
password, a vulnerable system might create an SQL query like this:
•SELECT * FROM users WHERE username = 'user_input' AND password = 
'user_input';
